BUILT ON META MODELS

Meta’s models see, plan and listen.
The safety gate decides.

Every model output is a proposal. Nothing moves until it passes the safety rules and carries a signed permit for that exact move. All four models run on the live site, and every call is recorded in the mission’s evidence.

MISSION PLANNING · META MODEL API

Muse Spark

Plans each mission from the site map and the robot’s own camera view, and replans when moves are refused.

STEP PROPOSALS · OPEN WEIGHTS

Muse Spark Open

Meta’s open-weights model proposes each next step, and can take over planning if the Meta API is unavailable.

VISION · META MODEL API

SAM 3.1

Finds people, spills and pallets in the robot’s camera and places them on the floor in metres, cross-checked against the sensors. It can only add caution, never remove it.

VOICE STOP · META MODEL API

Muse Voice Transcribe

Say “stop” and the robot stops. Voice can stop movement; it can never start it.

Models plan and perceive. Rules, permits and the robot controller decide what executes.

HOW MOVEMENT IS AUTHORISED

A plan proposes.
A permit authorises movement.

The planner suggests a move. Separate safety checks decide whether it may proceed. The robot controller then checks a signed permit: a permission for that specific move. STOP can always be requested without a movement permit.

What works today

Implemented building blocks: screened external site information; corroborated guidance that can tighten hazard restrictions; signed route experience filtered by context, freshness and source corroboration; independent policy checks and controller permits.

Operator release (live): a candidate lesson built from signed observations of at least two robots is evaluated, approved by a signed-in operator and released as one version. Planners use only released versions that match their site, map, policy and robot type; withdrawing or revising a version stops reuse. Every step is a signed audit event. This illustration uses scripted data; the working version is at Fleet learning. It shares advisory routing knowledge, not robot control skills or model weights.
